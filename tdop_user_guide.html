1 — What Is TDOP?

TDOP (Terminal D Operations Briefing) is the primary web tool within the Gate Gadget Initiative, created by Brad J. Sapit for DFW Terminal D gate coordinators and supervisors. It fetches live flight data from the Stand & Gate API, presents Terminal D gate flights and F-Hardstand operations in a side-by-side briefing grid, and provides one-click email, Teams, and PDF export actions to communicate the shift picture to every relevant ops team.

Live Data & Auto-Refresh

Briefing data pulled live from the Stand & Gate API each Generate and auto-refreshed on a timed cycle. Gate and pad reassignments are detected each cycle and flagged with an amber ⚠ badge.

Two-Column Briefing Grid

Left column: F-Hardstand operations. Right column: Terminal D gate flights. Each airline gets its own card with arrival and departure rows, inline editable fields, and per-leg controls.

State Persistence

Every ETA, ETD, pax count, note, cancellation flag, and gated state is auto-saved locally as you work. If the tab closes, click Load Saved on startup to restore the full session.

Multi-Channel Briefing Sends

Full-briefing emails, scoped handler emails, INTL Teams card and SeeSay Bussing chat posts (via Power Automate), Traffic and O/N Traffic lists, PDF exports, and a bus gate board — all from the same toolbar without switching tools.

3 — Airline Card Controls

Each airline card contains inline controls per flight leg plus card-level controls in the header.

ControlWhat It Does
ETA / ETD FieldClick the ETA or ETD cell and type the estimated time (e.g. 14:35). Overrides STA/STD in all exports — PDF, email, and Teams card. Leave blank to use the scheduled time.
Pax Count FieldEnter expected passenger count for the leg. Shown in the briefing card and carried into all exports. Useful for resource planning and gate assignments.
Note FieldPer-leg freeform text (up to 100 characters). Appears italicized beneath the flight row. Shown in all exports. Use for ACARS notes, gate remarks, or crew status.
✗ Cancel CheckboxMarks a leg as cancelled — strikes through red, CXL badge appears. If both legs of a hardstand flight are cancelled, the card moves to the terminal section and is removed from HS exports.
Gated ToggleCard-level toggle. When active, the card dims and all cells strike through, indicating the aircraft is blocked or on hold. The "GATED" label appears in the card header.
Card CheckboxSelects the card for multi-card operations. When two or more cards are checked, a selection toolbar appears for batch-export or targeted email of only those flights.
⚠ Gate/Pad Changed BadgeAmber badge when the API detects a reassignment since the baseline was set on first Generate. Hover the highlighted cell to see the original value in a tooltip.
🔴 +1 Next-Day BadgeRed badge on times that cross midnight — indicates the time belongs to the following calendar day. Auto-applied from the API's scheduled times.

4 — Running a Shift — Step by Step

1

Open TDOP & Check for Saved State

If a saved briefing from a previous session exists, the startup screen shows Load Saved alongside New Briefing. Load Saved restores all ETAs, notes, flags, and pax counts from the prior session.

2

Set Date & Shift Time Window

Select today's date and your shift start/end times in the header. If the date field is locked from the previous session, tap the 🔓 unlock icon to enable it.

TDOP defaults to the current date and a common shift window on fresh load.
3

Click Generate

Fetches live data from the Stand & Gate API. Status dot pulses amber while loading, turns green on success. Left column: F-Hardstand operations. Right column: Terminal D gate flights.

4

Enter ETAs & ETDs

Click into any ETA or ETD cell and type your estimated time. These override the scheduled STA/STD times in every export. Leave blank to use the scheduled time from the API.

5

Add Notes & Pax Counts

Use the note field under each leg for ACARS remarks, gate notes, or crew status. Use the pax field for expected passenger counts. Both appear in the PDF and email exports.

6

Flag Cancellations

Check the ✗ checkbox on any cancelled legs. The row strikes through in red. If both legs of a hardstand flight are cancelled, the card automatically moves to the terminal section.

7

Watch for Gate / Pad Changes

During auto-refresh, if a gate or pad is reassigned, the card gets an amber ⚠ badge and the changed cell highlights. Hover to see the original value. Baseline resets on Clear All and at 3:00 AM.

8

Send Briefings

Use ✉ All Ops for the full shift blast. Scoped buttons — HS Ops, LF Ops, INTL Ops, Swiss, WFS — for targeted sends. Bus Board when D5/D7 bus gate ops are active. PDF for a printed packet.

INTL Ops fires both email and Teams simultaneously — no second action needed.
9

End of Shift — Clear All

Click 🗑 Clear All to wipe all saved state, inputs, flags, and the gate-change baseline so the incoming coordinator starts completely clean.

5 — Tips, Notes & Good to Know

💾
Auto-save is always on. Every ETA, ETD, note, or pax count saves immediately to local storage. A saved indicator appears in the status bar. You never need to manually save.
🔄
Gate-change baseline. First Generate captures every gate/pad as the baseline. On each auto-refresh, new assignments are compared to that baseline. New flights added mid-shift seed with no flag. Baseline resets on Clear All and at 3:00 AM.
📋
Multi-select toolbar. Check two or more airline card checkboxes and a selection toolbar appears. Use it to export or email only those selected flights — useful for targeting specific gates or handlers without a full ops blast.
📅
Date lock. Once a briefing is generated, the date field locks to prevent accidental changes. Tap the 🔓 unlock icon to re-generate for a different date mid-session.
🌙
Dark mode. Manual toggle — does not follow OS settings. Preference held for the browser session. Night shift coordinators may prefer dark mode in the gate environment.
📡
INTL Ops Teams integration. The INTL Ops button sends to both email and Power Automate flow (prod-07). The Teams card appears as a flow bot post — not from your personal account. Both use the same 13:00–21:00 STA/ETA filter.
🚌
Bus Board. Use the Bus Board button whenever D5 or D7 bus station gates have active remote boarding. Built from flights already in the briefing — no extra data entry needed.
🔧
Equipment button. Opens the Ground Equipment Notification form. Select a handler, add equipment + location pairs, and send a formatted removal email without opening a separate tool.
🌙
O/N Traffic vs Traffic. The Traffic button follows your shift window picker — good for any shift. The O/N Traffic button is hardcoded to 21:00–08:00 and filters to overnight-designated stands only, making it a one-click report for the overnight team without adjusting any settings. No briefing generation required.
👁
SeeSay. Automatically posts an adaptive card in the Bussing chat via Power Automate, prompting staff to use the SeeSay app for IOC Specialist requests. The card includes a Open SeeSay App button linking directly to the mobile web version. Always available — does not require a briefing to be generated first.

6 — Future Enhancements — Roadmap

Features and improvements under consideration for future TDOP versions.

Operations

☀️ SY Ops — Sun Country Summer Bus Ops

Dedicated SY Ops button for seasonal summer operations when Sun Country uses bus boarding at D5A/D5B. Would email dfwops@suncountry.com and Menzies SY contacts with a bus-gate scoped briefing card.

Notifications
High Priority

📲 Teams — All Ops Channel Post

Extend the existing INTL Ops Teams webhook pattern to a full All Ops Teams post, sending the complete Terminal D briefing to a shared channel for supervisor review without opening email.

UX
Medium Priority

🕐 Shift Auto-Detection

Automatically detect the current shift (Mid / Day / Evening / Night) based on system time and pre-fill the shift time range on load, reducing clicks for coordinators at shift start.

Exports
Medium Priority

📋 Clipboard Copy for Email HTML

A "Copy HTML" option alongside each email send action so the formatted briefing card can be pasted directly into Outlook — useful on devices where mailto: links don't reliably open the mail client.

Operations
Medium Priority

🚌 D5A / D5B Split Bus Board

Update the Bus Board output to show D5A and D5B as two distinct rows, making clear which sub-gate each aircraft is assigned to. Currently both roll up to one D5 entry.

Future
Backlog

Add a stats footer to the PDF export showing total flight count, total pax, international vs. domestic split, and hardstand vs. gate split for the briefing period.

7 — Shift Start Checklist

1

Open TDOP. If a saved state exists, decide: Load Saved (continue prior session) or New Briefing (start fresh).

2

Set date and shift window in the header. Unlock the date field if needed.

3

Click Generate. Wait for the status dot to turn green and the briefing grid to populate.

4

Enter ETAs / ETDs for each flight leg — type directly into the ETA or ETD cells.

5

Add notes and pax counts as needed — these carry into all exports.

6

Flag any known cancellations using the ✗ checkbox on the affected leg.

7

Send briefings — All Ops email, individual handler sends, Bus Board if needed.

8

Monitor during shift — watch for ⚠ gate/pad change badges on auto-refresh.

9

Use Equipment button for any ramp equipment issues that arise mid-shift.

10

End of shift: Click 🗑 Clear All to reset for the incoming coordinator.
